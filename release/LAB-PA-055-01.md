# LAB-PA-055-01 · SBOM, firmas y tabla de vulnerabilidades de una versión publicada

| Campo | Detalle |
| --- | --- |
| Requisitos | BT-055 (inventario de componentes y gestión de vulnerabilidades), BT-054, BT-048 |
| Objetivo | Comprobar que la versión publicada trae el SBOM del producto y de cada imagen, que todo archivo e imagen está firmado por el flujo de versión del repositorio y que la tabla de vulnerabilidades y el OpenVEX dicen lo mismo, sin filas cortadas. |
| Comando | `tools/release/verificar-version.sh <versión>` (por ejemplo `tools/release/verificar-version.sh 1.2.0`) |
| Condiciones previas | Versión publicada en <https://github.com/insigne123/yago-nexo/releases> por `.github/workflows/release.yml`. Equipo con `gh`, `cosign` 2.x, Docker, `jq`, `sha256sum` y Node.js 22, y acceso a GitHub, a GHCR y a Docker Hub (imagen `cyclonedx/cyclonedx-cli`). |
| Datos | Los archivos de la versión (no se usan datos de personas). |
| Carga | No aplica. |
| Componentes | Flujo de versión de GitHub Actions, Sigstore (Fulcio y Rekor), GHCR, cosign, syft, grype y cyclonedx-cli. |

## Pasos y resultado esperado

El script ejecuta estos pasos en orden y se detiene en el primero que falla. También se pueden correr a mano en la
carpeta descargada (`gh release download v<versión> -R insigne123/yago-nexo -D <carpeta>`).

| # | Paso | Comando | Resultado esperado |
| --- | --- | --- | --- |
| 1 | Sumas de todos los archivos | `sha256sum -c CHECKSUMS.txt` | Todas las líneas en `OK`. |
| 2 | Firma de cada archivo | `cosign verify-blob --bundle <archivo>.sigstore.json --certificate-identity-regexp "$IDENTIDAD" --certificate-oidc-issuer "$EMISOR" <archivo>` | `Verified OK` para cada archivo, incluidos los SBOM, la tabla y el OpenVEX. |
| 3 | Firma y SBOM de cada imagen propia (`IMAGENES.txt`) | `cosign verify <imagen@digest> ...` y `cosign verify-attestation --type cyclonedx <imagen@digest> ...` | Firma válida y atestación CycloneDX válida, emitidas por la misma identidad. |
| 4 | Validez de cada SBOM | `docker run --rm -v "$PWD:/d:ro" cyclonedx/cyclonedx-cli:0.33.1 validate --input-file /d/<sbom> --input-version v1_6 --fail-on-errors` | `BOM validated successfully` para `sbom-nexo-<versión>.cdx.json` y cada `sbom-imagen-*.cdx.json`. |
| 5 | Tabla, JSON y OpenVEX | `node tools/release/comprobar-vulnerabilidades.mjs <carpeta> <versión>` | Mismo número de filas en la tabla Markdown y en el JSON, totales por imagen correctos y una declaración OpenVEX por cada vulnerabilidad crítica. |

Con:

```bash
IDENTIDAD='^https://github.com/insigne123/yago-nexo/\.github/workflows/release\.yml@refs/(heads/main|tags/v.+)$'
EMISOR=https://token.actions.githubusercontent.com
```

La identidad solo acepta firmas hechas por `release.yml` corriendo desde `main` o desde una etiqueta `v*`: una
firma hecha desde otra rama no pasa.

## Qué revisar además, a la vista

- `sbom-nexo-<versión>.cdx.json`: los componentes `@nexo/*` aparecen con `purl` `pkg:npm/%40nexo/<paquete>@<versión>`;
  los de terceros tienen `scope: required` (ejecución) o `scope: excluded` (desarrollo, construcción o
  laboratorio) y la propiedad `nexo:uso`. `LICENCIAS.md` resume los mismos totales.
- `vulnerabilidades-nexo-<versión>.md`: el resumen por imagen y el detalle con todas las severidades; ninguna celda
  termina en «…».
- `vex-nexo-<versión>.openvex.json`: cada crítica con su estado; las que no tienen análisis registrado en
  `tools/release/vex-decisiones.json` quedan `under_investigation` con lo que informó grype.

## Tolerancia

Ninguna: cualquier suma, firma, SBOM o diferencia entre la tabla y el OpenVEX hace fallar el caso.

## Registro

Guardar la salida completa del script junto con el número de versión y el commit de la etiqueta:

```bash
tools/release/verificar-version.sh 1.2.0 2>&1 | tee LAB-PA-055-01-1.2.0.log
```
